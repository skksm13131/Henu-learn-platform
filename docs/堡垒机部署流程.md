# LabCore 堡垒机部署流程

更新时间：2026-07-03
适用环境：`https://labcore.henu.edu.cn/`
线上应用目录：`/opt/learning-platform`

> 本文不记录服务器、数据库密码或其他敏感凭据。部署前请向项目负责人获取当次使用的堡垒机账号、数据库密码和上传方式。

## 1. 部署原则

1. 在本地完成后端和前端构建，服务器不在线安装依赖。
2. 每次部署前备份数据库、后端 Jar、前端 `dist` 和生产配置。
3. 日常部署只替换后端 Jar 和前端 `dist`。
4. 不覆盖 `/opt/learning-platform/data`，其中包含 Notebook 模板、考核说明材料和学生提交文件。
5. 数据库迁移脚本只在对应功能首次上线时执行，不随每次代码部署重复执行。
6. 后端必须以 `/opt/learning-platform` 为工作目录启动，否则相对路径 `data/...` 会指向错误位置，造成“文件不存在”。

## 2. 线上目录说明

```text
/opt/learning-platform/
├── backend/
│   ├── labcore.jar
│   └── application.properties
├── frontend/
│   └── dist/
├── bin/
│   ├── start-backend.sh
│   └── stop-backend.sh
├── data/
│   ├── learning-templates/
│   ├── assignment-materials/
│   └── assignment-submissions/
├── logs/
│   └── labcore.log
├── backup/
└── mysql/
    └── bin/
```

各数据目录用途：

- `data/learning-templates`：学习卡片 Notebook 模板。
- `data/assignment-materials`：教师为考核要求上传的图片、视频和文档。
- `data/assignment-submissions`：学生提交的文档和视频。

## 3. 部署前检查

在本地仓库执行：

```powershell
git status --short
git log -1 --oneline
git fetch origin
git rev-parse HEAD
git rev-parse origin/master
```

正式部署时，本地 `HEAD` 应与计划部署的 GitHub 提交一致。记录提交哈希，便于部署后核对和回滚。

检查本地环境：

```powershell
java -version
mvn -version
node -v
npm -v
```

## 4. 本地构建

### 4.1 构建后端

在项目根目录执行：

```powershell
mvn clean package -DskipTests
```

后端产物：

```text
target/LabCore-0.0.1-SNAPSHOT.jar
```

### 4.2 构建前端

```powershell
Set-Location web-study-1.0.1/package
npm install
npm run build
Set-Location ../..
```

前端产物：

```text
web-study-1.0.1/package/dist/
```

如果依赖没有变化且本机已有完整的 `node_modules`，可不重复执行 `npm install`。

### 4.3 推荐部署包结构

用日期和时间作为版本号，例如 `20260703-1530`：

```text
labcore-release-20260703-1530/
├── backend/
│   └── app.jar
├── frontend/
│   └── dist/
├── db/                         # 仅在本次确有数据库迁移时放入
│   └── migration.sql
├── COMMIT.txt
└── README.md
```

将后端 Jar 重命名为 `app.jar` 放入部署包，并把本次 Git 提交哈希写入 `COMMIT.txt`。部署包中不要包含：

```text
application.properties
data/
数据库密码
学生上传文件
本地日志
```

压缩为：

```text
labcore-release-20260703-1530.zip
```

## 5. 上传部署包

将部署包上传到堡垒机：

```text
/root/upload/labcore-release-20260703-1530.zip
```

进入服务器后先确认文件：

```bash
cd /root/upload
ls -lh labcore-release-20260703-1530.zip
unzip -l labcore-release-20260703-1530.zip
```

解压到独立目录：

```bash
cd /root/upload
unzip -q labcore-release-20260703-1530.zip -d labcore-release-20260703-1530
cd /root/upload/labcore-release-20260703-1530
find . -maxdepth 3 -type f -ls
```

确认包内至少存在：

```text
backend/app.jar
frontend/dist/index.html
```

## 6. 服务器部署前备份

### 6.1 设置本次版本变量

```bash
VERSION=20260703-1530
APP_DIR=/opt/learning-platform
PKG_DIR=/root/upload/labcore-release-$VERSION
BACKUP_DIR=$APP_DIR/backup/release-$VERSION
mkdir -p "$BACKUP_DIR"
```

### 6.2 备份应用文件

```bash
cp -a "$APP_DIR/backend/labcore.jar" "$BACKUP_DIR/labcore.jar"
cp -a "$APP_DIR/backend/application.properties" "$BACKUP_DIR/application.properties"
cp -a "$APP_DIR/frontend/dist" "$BACKUP_DIR/frontend-dist"
```

确认备份：

```bash
find "$BACKUP_DIR" -maxdepth 2 -type f -ls
```

### 6.3 备份数据库

使用 `mysqldump`，命令执行后按提示输入数据库密码。堡垒机终端建议直接复制下面的单行命令，避免反斜杠续行被拆开执行：

```bash
/opt/learning-platform/mysql/bin/mysqldump -uroot -p -h127.0.0.1 -P3306 --single-transaction --routines --triggers --databases labcore > "$BACKUP_DIR/labcore.sql"
```

如果终端已经出现单独的 `>` 提示符，先按 `Ctrl+C` 取消未完成的命令，再重新复制完整单行命令。

检查备份不是空文件：

```bash
ls -lh "$BACKUP_DIR/labcore.sql"
test -s "$BACKUP_DIR/labcore.sql"
```

## 7. 数据库迁移

只有本次版本明确包含数据库结构变化时才执行本节。纯前后端更新直接跳到第 8 节。

先查看 SQL，确认不是演示数据或完整初始化脚本：

```bash
sed -n '1,160p' "$PKG_DIR/db/migration.sql"
```

执行迁移：

```bash
/opt/learning-platform/mysql/bin/mysql \
  -uroot -p \
  -h127.0.0.1 -P3306 \
  labcore < "$PKG_DIR/db/migration.sql"
```

注意：

- 不要在生产库执行 `db/demo/seed_assessment_demo.sql`。
- 不要把 `labcore_full_init.sql` 当作日常升级脚本。
- 能力考核模块已上线后，不要在每次部署时重复执行首次建表脚本。

## 8. 替换应用并重启

### 8.1 停止后端

优先使用现有脚本：

```bash
"$APP_DIR/bin/stop-backend.sh"
```

确认旧进程已经停止：

```bash
ps -ef | grep '[l]abcore.jar'
```

如果停止脚本失效，先查出 PID，再正常结束进程：

```bash
PID=$(pgrep -f '/opt/learning-platform/backend/labcore.jar' | head -1)
echo "$PID"
kill "$PID"
```

再次确认进程消失后再继续，不要在旧进程仍运行时直接覆盖 Jar。

### 8.2 替换后端

```bash
cp -a "$PKG_DIR/backend/app.jar" "$APP_DIR/backend/labcore.jar"
ls -lh "$APP_DIR/backend/labcore.jar"
```

### 8.3 替换前端

先在同一文件系统内准备新目录，再切换：

```bash
rm -rf "$APP_DIR/frontend/dist.new"
cp -a "$PKG_DIR/frontend/dist" "$APP_DIR/frontend/dist.new"
mv "$APP_DIR/frontend/dist" "$APP_DIR/frontend/dist.old-$VERSION"
mv "$APP_DIR/frontend/dist.new" "$APP_DIR/frontend/dist"
```

确认前端入口存在：

```bash
test -f "$APP_DIR/frontend/dist/index.html"
ls -lh "$APP_DIR/frontend/dist/index.html"
```

### 8.4 检查生产配置

```bash
grep -E '^(server.port|spring.jackson.time-zone|labcore.assignment.(upload|material)-dir|spring.servlet.multipart.max-(file|request)-size)=' \
  "$APP_DIR/backend/application.properties"
```

应重点确认：

```properties
spring.jackson.time-zone=Asia/Shanghai
labcore.assignment.upload-dir=/opt/learning-platform/data/assignment-submissions
labcore.assignment.material-dir=/opt/learning-platform/data/assignment-materials
spring.servlet.multipart.max-file-size=300MB
spring.servlet.multipart.max-request-size=330MB
```

如果线上仍使用相对路径 `data/...` 也可以，但必须保证后端工作目录是 `/opt/learning-platform`。

### 8.5 启动后端

优先使用现有脚本：

```bash
cd "$APP_DIR"
"$APP_DIR/bin/start-backend.sh"
```

如果需要手工启动，必须先进入应用根目录，并显式指定北京时间：

```bash
cd /opt/learning-platform
nohup java -Duser.timezone=Asia/Shanghai \
  -jar /opt/learning-platform/backend/labcore.jar \
  --spring.config.location=/opt/learning-platform/backend/application.properties \
  > /opt/learning-platform/logs/labcore.log 2>&1 &
```

### 8.6 重新加载 Nginx

前端是静态文件，通常替换 `dist` 后即可生效。建议检查并重新加载 Nginx：

```bash
nginx -t
nginx -s reload
```

能力考核视频最大允许 300 MB，Nginx 对应站点配置中的上传限制不能小于后端限制，例如：

```nginx
client_max_body_size 330m;
```

修改 Nginx 配置后再次执行 `nginx -t` 和 `nginx -s reload`。

## 9. 部署后检查

### 9.1 检查进程和工作目录

```bash
PID=$(pgrep -f '/opt/learning-platform/backend/labcore.jar' | head -1)
echo "PID=$PID"
ps -fp "$PID"
readlink -f "/proc/$PID/cwd"
```

工作目录应输出：

```text
/opt/learning-platform
```

### 9.2 检查端口和日志

```bash
ss -lntp | grep 18080
tail -n 100 /opt/learning-platform/logs/labcore.log
```

日志应包含应用启动成功信息，不应持续出现数据库连接失败、端口占用或配置文件找不到。

如果 `tail -f` 持续占用终端，按 `Ctrl+C` 退出；普通 `tail -n 100` 执行完会自动返回命令行。

### 9.3 检查持久化目录

```bash
find /opt/learning-platform/data -maxdepth 2 -type d -print
find /opt/learning-platform/data/assignment-materials -type f | head
find /opt/learning-platform/data/assignment-submissions -type f | head
```

检查数据库记录指向的相对路径时，实际文件应位于：

```text
/opt/learning-platform/data/<数据库中的 stored_path>
```

### 9.4 页面验收

访问：

```text
https://labcore.henu.edu.cn/
```

至少完成以下检查：

1. 管理员和学生账号均可登录。
2. 最后登录时间显示为北京时间。
3. 学习卡片与 Notebook 在线练习可以打开。
4. 学生端能力考核列表和详情正常。
5. 已过截止时间的考核不能提交。
6. 教师上传的考核说明图片、视频可以查看。
7. 学生可以上传文档或视频并提交。
8. 管理员可以查看提交、下载单个附件和批量下载。
9. 管理员可以评分、填写评语和退回重交。

建议使用一个临时测试考核完成“创建、发布、学生提交、教师批改”的闭环验收。

## 10. 回滚流程

发现严重问题时，先停止后端：

```bash
APP_DIR=/opt/learning-platform
VERSION=20260703-1530
BACKUP_DIR=$APP_DIR/backup/release-$VERSION
"$APP_DIR/bin/stop-backend.sh"
```

恢复后端、前端和配置：

```bash
cp -a "$BACKUP_DIR/labcore.jar" "$APP_DIR/backend/labcore.jar"
cp -a "$BACKUP_DIR/application.properties" "$APP_DIR/backend/application.properties"
rm -rf "$APP_DIR/frontend/dist"
cp -a "$BACKUP_DIR/frontend-dist" "$APP_DIR/frontend/dist"
```

重新启动：

```bash
cd "$APP_DIR"
"$APP_DIR/bin/start-backend.sh"
nginx -t
nginx -s reload
```

只有在本次部署执行了数据库迁移且确认必须回退数据库时，才恢复数据库备份：

```bash
/opt/learning-platform/mysql/bin/mysql \
  -uroot -p \
  -h127.0.0.1 -P3306 \
  labcore < "$BACKUP_DIR/labcore.sql"
```

数据库回滚会覆盖部署之后产生的新业务数据，执行前必须获得项目负责人确认。

## 11. 常见问题

### 11.1 图片、视频或学生附件提示“文件不存在”

依次检查：

```bash
PID=$(pgrep -f '/opt/learning-platform/backend/labcore.jar' | head -1)
readlink -f "/proc/$PID/cwd"
grep 'labcore.assignment.*-dir' /opt/learning-platform/backend/application.properties
find /opt/learning-platform/data/assignment-materials -type f | head
find /opt/learning-platform/data/assignment-submissions -type f | head
```

常见原因：

- Java 工作目录不是 `/opt/learning-platform`。
- 数据库有文件记录，但实际文件仍留在旧部署包目录 `/root/upload/.../data`。
- 部署时错误覆盖或遗漏了线上 `data/`。
- 配置使用了相对路径，但启动位置改变。

### 11.2 时间与北京时间相差 8 小时

检查：

```bash
ps -ef | grep '[l]abcore.jar'
grep '^spring.jackson.time-zone=' /opt/learning-platform/backend/application.properties
date
```

Java 启动参数应包含：

```text
-Duser.timezone=Asia/Shanghai
```

配置应包含：

```properties
spring.jackson.time-zone=Asia/Shanghai
```

### 11.3 上传大视频失败

同时检查三层限制：

1. Nginx：`client_max_body_size 330m;`
2. Spring Boot：单文件 `300MB`、单请求 `330MB`。
3. 堡垒机或上游代理是否还有额外上传限制。

### 11.4 终端看起来“卡住”

- `tail -f`、`journalctl -f` 会持续监听日志，按 `Ctrl+C` 退出。
- 命令行出现 `>` 通常表示上一行引号、反斜杠或括号没有闭合，按 `Ctrl+C` 取消后重新输入。
- 执行大文件下载时客户端提前断开，日志中的 `Broken pipe` 通常表示连接被用户或浏览器中止，不等于服务器文件丢失。
